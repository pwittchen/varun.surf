# Publishing varun.surf on Google Play

This is the plan and checklist for the first Google Play release of `surf.varun.app`, and for the
updates after it. Section numbers like "spec 12.1" point to [SPEC.md](SPEC.md).

**Where things stand (2026-10-25)**

| Area | State |
|---|---|
| Application id | `surf.varun.app`. It can't be changed after the first upload (spec D2) |
| SDK levels | minSdk 28, targetSdk 36, compileSdk 37. Target 36 meets the Play requirement for new apps in 2026 |
| Release build | R8 + resource shrinking, signed from `VARUN_*` env vars, `versionName` from the tag, `versionCode` from the CI run number |
| CI | An `android-v*` tag builds a signed AAB and uploads it to the **production** track for all users (`r0adkll/upload-google-play`). It goes live after review and a manual "Publish changes" (managed publishing) |
| Permissions | `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_COARSE_LOCATION` (foreground only, asked for when needed), `POST_NOTIFICATIONS` (asked for when the first alert is created) |
| Privacy | No analytics, ads, Firebase or crash SDK. Location stays on the device. The in-app privacy text is in `feature/about` |
| Backup | The session cookie and the Room cache are excluded. Favourites, alerts and settings are backed up |
| Native code | MapLibre 13.7.1. Its `.so` files support 16 KB pages, which Play requires for targetSdk 35+ |
| Done | Privacy policy at `/privacy` (EN + PL), a report action under the AI analysis and the ICM reading, CI uploads as a draft with the R8 mapping and release notes |
| **Missing** | A committed baseline profile. `assetlinks.json` is in the repo (`src/frontend/assets/`) and goes live with the next backend deploy |

## 1. Release plan

### Phase 0: Accounts and decisions (one-off)

1. **Play Console developer account.** Use the existing account or register one ($25). Finish
   identity verification and add a public developer email and website (`https://varun.surf`).
   - **Personal accounts created after 13 Nov 2023** must run a **closed test with at least 12
     testers opted in for 14 days in a row** before they can apply for production access. Plan
     for about 3 weeks between the first closed build and production. Organisation accounts
     (these need a D-U-N-S number) skip this step.
2. **Developer name** shown on the listing. This can be a personal name or "varun.surf".
3. **Play App Signing** (required for new apps). Google holds the app signing key. The keystore
   in the GitHub secret `ANDROID_KEYSTORE_BASE64` is only the **upload key**. Keep an offline
   backup of the upload keystore and its passwords; if it's lost, Play support can reset the
   upload key.
4. **Content rights.** Settle these before writing the listing:
   - Windguru forecasts, the meteo.pl ICM meteogram and live station data are shown in the app.
     Credit the sources in About → Data sources and the full description, and don't use
     Windguru's or IMGW's branding in store graphics.
   - **Esri World Imagery** (the default basemap): check that using it in a published app with
     attribution complies with Esri's terms. If it doesn't, make OpenFreeMap the default.
     Either way, the map attribution has to stay visible.
   - **Spot photos** (spec Q5): use only photos you have the rights to in screenshots and the
     feature graphic.

### Phase 1: Backend and web prerequisites

These go into the backend repo and are deployed before the app ships.

1. **Privacy policy page** *(done: `src/frontend/html/privacy.html`, served at `/privacy`)*, in EN and PL. Play requires one for
   every app, and in particular for apps that request location. It has to be public, not a
   PDF, not geo-blocked, and needs no session cookie (it is a page visit, which the session
   filter never gates). It should cover:
   - no accounts, analytics, ads or crash reporting
   - coarse location used only on the device to compute distances, never transmitted
   - favourites, alerts and settings stored on the device and included in Android backup
   - requests to varun.surf carry a functional, non-identifying session cookie and an
     `X-Client` header. Server logs and nginx keep IP addresses for rate limiting (give the
     retention period)
   - third parties that receive the device's IP and the map area being viewed: the Esri and
     OpenFreeMap tile servers, plus any image hosts for spot photos
   - AI analyses are generated by OpenAI from forecast data only; no user data is sent
   - a contact email
2. **`/.well-known/assetlinks.json`** (spec 12.1), served as `application/json`, exempt from the
   session filter, `no-cache`. It must list the **Play app signing certificate SHA-256** (Play
   Console → Test and release → App integrity), not the upload key. Add the upload key's
   fingerprint as well if sideloaded CI builds should also verify.
   ```json
   [{
     "relation": ["delegate_permission/common.handle_all_urls"],
     "target": {
       "namespace": "android_app",
       "package_name": "surf.varun.app",
       "sha256_cert_fingerprints": ["<PLAY APP SIGNING SHA-256>"]
     }
   }]
   ```
   The fingerprint only exists once the app is created in Play Console and the first AAB is
   uploaded, so this step comes after Phase 3.1.
3. *(Recommended)* **Feature flags in `/api/v1/status`** (spec 12.4). With AI and ICM off in
   production, a Play reviewer would press the button, confirm, and get a 503, which looks like
   a broken feature. Either hide the buttons when the feature is off, or make sure the flags
   are on in production.

### Phase 2: App changes before the first upload

1. **AI content reporting** *(done)*. Play's AI-Generated Content policy requires apps that
   show generative AI output to let users report or flag offensive content without leaving the
   app. A "Report" button under the AI analysis and under the ICM reading opens a prefilled
   email to `hello@varun.surf` in the user's mail app (`Intents.email`), so the app itself
   collects nothing and the Data safety answers stay "None".
2. **Native debug symbols** *(not possible)*. The prebuilt `.so` files (MapLibre, AndroidX
   graphics-path, DataStore) ship already stripped, so `ndk.debugSymbolLevel` has nothing to
   extract. Play shows a "no native debug symbols" warning, which does not block a release.
3. **R8 mapping in CI** *(done)*. The upload step passes
   `mappingFile: android/app/build/outputs/mapping/release/mapping.txt`.
4. **Release notes in CI** *(done)*. `whatsNewDirectory: android/distribution/whatsnew` holds
   `whatsnew-en-US` and `whatsnew-pl-PL`, each 500 characters or fewer. Rewrite them for every
   release.
5. **Draft-app status** *(done)*. Until the app has been reviewed and published once, the Play
   API only accepts `status: draft`. The upload step reads the `PLAY_RELEASE_STATUS` repository
   variable and defaults to `draft`; set it to `completed` after the first publish.
6. **Baseline profile.** Run `./gradlew :app:generateBaselineProfile` on a device and commit the
   result so the first install gets the startup improvement.
7. **Version 1.0.0.** Tag `android-v1.0.0`. `versionCode` is `github.run_number`, so it always
   increases as long as releases come only from CI. A local `bundleRelease` without
   `VERSION_CODE` gets code 1, which is fine for the first manual upload only.

### Phase 3: Play Console setup

1. **Create the app.** Name `varun.surf`, default language English (United States), type App,
   Free. Accept the Developer Program Policies and US export laws declarations. Free apps
   can't be made paid later, which is fine here.
2. **First AAB, uploaded by hand.** The API can't push to an app that has never had a build, so
   build the signed AAB locally or download the CI artifact and upload it to **Internal
   testing** in the console. This creates the app signing key. Copy its SHA-256 for
   Phase 1.2.
3. **Service account for CI.** Create a Google Cloud service account with a JSON key. Invite
   it in Play Console → Users and permissions, granting access to this app only with release
   permissions to testing tracks, and store the key as `PLAY_SERVICE_ACCOUNT_JSON`.
4. **App content declarations** (Policy → App content). See checklist section 2.4 for the
   answers.
5. **Store listing** in EN plus a PL translation. See checklist section 2.5.
6. **Store settings.** Category **Weather** (Sports is the alternative). Tags: weather, wind,
   kitesurfing. Contact email and website.
7. **Countries.** All countries, or at least every country the spots cover (59).

### Phase 4: Testing tracks

1. **Internal testing** (up to 100 testers, available within minutes). Install from Play on at
   least one physical phone and run the smoke test in checklist section 2.7. Read the
   **pre-launch report** (Play runs Robo tests on real devices) and fix crashes and
   accessibility warnings.
2. **Closed testing** (required for new personal accounts):
   - make an email list or Google Group with **12 or more** testers, such as kitesurfing friends
     and the local club. Ask them to opt in on the web link, install, and keep the app for the
     whole 14 days
   - push at least one update during the test; Play looks at engagement
   - collect feedback through the private feedback channel or by email
   - spec 11 requires **≥ 99.5 % crash-free users** before production; check this in Android
     vitals
3. **Apply for production access** once the 14 days have passed. The form asks how testers were
   recruited, what feedback came in and what changed. Answer specifically. Review typically
   takes up to 7 days.

### Phase 5: Production launch

1. Promote the tested release to **Production** with a **staged rollout**: 10 % → 50 % (after
   2–3 days with no new clusters in vitals) → 100 %.
2. The first production review can take several days. Don't announce a launch date until the
   app has been approved. Managed publishing lets you control the moment it goes live.
3. After launch:
   - check App Links verification: `adb shell pm get-app-links surf.varun.app` should show
     `verified` for `varun.surf`
   - add a Play badge or link on varun.surf (sidebar or About modal) and to README.md
   - announce it

### Phase 6: Ongoing releases

- Every release goes tag → production review → **Publish changes** (managed publishing).
  CI uploads straight to production at 100 %, so smoke-test the release build before tagging.
- Watch Android vitals thresholds (user-perceived crash rate < 1.09 %, ANR rate < 0.47 %).
  Going over them reduces the app's visibility on Play.
- Raise **targetSdk** within a year of each Android release. Play's deadline is 31 August each
  year, and updates are blocked once it passes.
- Policy updates arrive in the Play Console inbox and by email. Re-check the Data safety form
  whenever a dependency or feature changes what data leaves the device (for example, adding a
  crash reporter or FCM alerts from spec 12.6).
- Keep the upload keystore backed up, and rotate the service account key every year.

## 2. Checklist

### 2.1 Account and legal
- [ ] Play Console account active, identity verified, developer name and email set
- [ ] Account type known (personal → closed test with 12 testers for 14 days is mandatory)
- [ ] Upload keystore backed up offline (keystore file + both passwords + alias)
- [ ] Rights confirmed for spot photos used in the listing (spec Q5)
- [ ] Esri World Imagery terms checked for app use, or OpenFreeMap made the default
- [ ] Data sources credited in About and in the full description

### 2.2 Backend
- [x] `https://varun.surf/privacy` (EN + PL), works without a cookie, linked from the web footer
- [ ] Privacy page deployed; access-log retention and the DataFast cookie wording checked against reality
- [ ] `/.well-known/assetlinks.json` live with the Play app signing SHA-256, `application/json`, no cookie, no redirect
- [ ] AI and ICM either enabled in production or hidden in the app when disabled
- [ ] nginx rate limits leave room for app traffic (`X-Client: varun-android/*`)

### 2.3 App build
- [x] AI output report action (analysis + ICM), EN + PL strings
- [x] CI uploads the R8 mapping file and release notes; status `draft` until the first publish
- [ ] `PLAY_RELEASE_STATUS` repository variable set to `completed` after the first publish
- [ ] Baseline profile generated and committed
- [ ] `./gradlew lintDebug test assembleRelease` green
- [ ] Release AAB installed on a physical device (`bundletool` or internal track) with **R8 on**: lists, spot, map, widgets, alerts all work (serialization and reflection survive minification)
- [ ] No debug logging in release (Timber is planted only when `BuildConfig.DEBUG`)
- [ ] `versionName` 1.0.0 from the `android-v1.0.0` tag; `versionCode` > any previously uploaded
- [ ] Launcher icon: adaptive + monochrome render correctly (light, dark, themed icons)
- [ ] Polish device shows Polish UI, `spotInfoPL`, `aiAnalysisPl`, and the Polish store listing
- [ ] 200 % font scale and TalkBack pass on main screens (spec 8.2)
- [ ] Offline launch after one successful start shows cached data with no error dialogs (spec 11)

### 2.4 App content declarations (Play Console → Policy → App content)
- [ ] **Privacy policy**: `https://varun.surf/privacy`
- [ ] **App access**: all functionality available without special access (no login)
- [ ] **Ads**: No ads
- [ ] **Content rating** (IARC questionnaire): category "Reference, News, or Educational" / utility. No violence, sexual content, gambling or user-to-user communication. Answer the questions about AI-generated content truthfully. Expected rating: Everyone / PEGI 3
- [ ] **Target audience**: 13+ or 18+ only. Including under-13 brings in the Families policy and isn't needed. Not "appealing to children"
- [ ] **News app**: No
- [ ] **COVID-19 tracing**: No
- [ ] **Data safety**:
  - Data collected: **None**. Coarse location is processed only on the device and is never transmitted, so under Play's definitions it isn't "collected"
  - Data shared: **None**
  - Data encrypted in transit: Yes (HTTPS only, cleartext disabled)
  - Users can request deletion: not applicable (nothing collected). Uninstalling or clearing storage removes the local data
  - Re-check this if the AI report action sends anything to the backend (an email address or free text would count as collected data)
- [ ] **Government app**: No
- [ ] **Financial features**: None
- [ ] **Health apps**: No
- [ ] **Location permission**: foreground only. No background location declaration needed (alerts and widgets don't use location)
- [ ] **Foreground service / exact alarms / full-screen intent**: none used, nothing to declare
- [ ] **Advertising ID**: the app doesn't use it. Declare "No"; nothing in the dependencies adds `AD_ID`. Confirm in the merged manifest

### 2.5 Store listing (EN-US + PL-PL)
- [ ] **App name** (≤ 30 chars): `varun.surf – kite forecast`
- [ ] **Short description** (≤ 80 chars), e.g. EN "Live wind and forecasts for 800+ kitesurfing spots worldwide" / PL "Wiatr na żywo i prognozy dla ponad 800 spotów kitesurfingowych"
- [ ] **Full description** (≤ 4000 chars): spots, live stations, multi-model forecasts, wind map with particles, favourites, widgets, wind alerts, kite calculator, AI analysis on demand, no ads, no account, no tracking, data sources credited. No keyword stuffing, no mention of other apps
- [ ] **App icon** 512 × 512, 32-bit PNG, ≤ 1 MB (made from `logo.png`, same as the launcher icon)
- [ ] **Feature graphic** 1024 × 500 JPG/PNG, without important text near the edges
- [ ] **Phone screenshots**: 4–8, 1080 × 1920 or larger (9:16), both languages: spots list, spot detail with live + forecast, wind map with field overlay, widgets on the home screen, alerts, calculator. Use real data and owned photos only
- [ ] **Tablet screenshots** (7" and 10"), optional but they help with large-screen eligibility, since the app has a navigation rail ≥ 600 dp
- [ ] *(Optional)* promo video (YouTube URL)
- [ ] Contact email, website `https://varun.surf`, privacy policy URL
- [ ] Category Weather, tags chosen

### 2.6 Release mechanics
- [ ] App created in Play Console; first AAB uploaded **by hand** to Internal testing
- [ ] App signing SHA-256 copied into `assetlinks.json` and deployed
- [ ] Service account invited (this app, with the production release permission)
- [ ] GitHub secrets set: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `PLAY_SERVICE_ACCOUNT_JSON`
- [ ] Tag `android-vX.Y.Z` pushed → workflow uploads to production (as a draft until `PLAY_RELEASE_STATUS` is `completed`)

- [ ] Pre-launch report: no crashes; accessibility and security warnings reviewed
